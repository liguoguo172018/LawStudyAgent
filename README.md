# LawStudyAgent

> An open-source AI study skill designed for law students, helping them organize legal learning materials, build structured knowledge systems, identify learning gaps, and improve their learning processes.

LawStudyAgent 是一个面向法学学习者的开源 AI 学习 Skill，旨在将 AI 从日常问答工具转变为能够辅助课程学习、知识管理、学习诊断和复习规划的学习助手。

当前版本：**v0.1.0（2026-11-10，早期实验版本）**

## 1. 项目介绍

法学生并不缺资料：教材、课件、课堂笔记、法条、案例、老师的口头强调，往往同时存在。真正麻烦的是把这些材料组织成**能复习、能检测、能持续维护**的结构，并且知道自己到底哪里没学会。

LawStudyAgent 尝试解决这个问题。它以 [Agent Skills](https://agentskills.io/specification) 规范组织为一组可被 AI 宿主加载的指令、规则与模板，让 AI 在辅导法律学习时做四件事：

- **整理**：把课程资料变成章节结构、知识点条目和知识地图。
- **讲解**：解释法律概念、辨析易混制度、辅助案例分析。
- **诊断**：用题目和作答证据判断掌握程度，记录薄弱点。
- **复习**：依据实际表现安排有针对性的复习，而不是简单地“再看一遍”。

项目定位：

- 面向法学专业学生及其他法律学习者。
- 以 Agent Skill 为主要交付形式，不绑定特定模型或商业产品。
- 采用**通用学习内核 + 独立课程模块**的设计，不把整个项目限定在某一门课。
- 支持用户导入自己的课程资料，个人数据保存在本地工作区。
- 鼓励不同学校的学生共同建设课程模块与学习工作流。

> 重要边界：LawStudyAgent 是学习工具，不是法律服务。它不提供法律意见，不预测裁判结果，也不保证输出内容为现行有效的法律知识。任何用于考试、实务或正式写作的结论，都应回到权威来源核验。

## 2. 项目背景与设计理念

### 2.1 从“单次问答”到“持续学习”

传统 AI 对话以一次提问、一次回答为中心。对话结束后，知识结构、学习进度和薄弱点大多留在聊天记录里：下次开新会话，AI 不知道你学到哪、哪里错过、上次的错题是否真的修复。对法学这种体系性强、概念密集、需要反复辨析的学科，这种模式很难支撑一学期甚至更长的学习。

LawStudyAgent 把学习组织成一个持续的工作流：

```text
课程资料导入 → 知识体系构建 → 学习与理解 → 练习与诊断
      ↑                                          ↓
      └──────── 针对性复习 ← 知识漏洞记录 ←──────┘
```

每一步都有对应的文件产物：课程配置、知识点条目、学习记录、薄弱点档案、复习队列。AI 在新会话中读取这些文件，就能接着上次的状态继续，而不是从零开始。

### 2.2 五条设计理念

| 从 | 到 | 在项目中的体现 |
| --- | --- | --- |
| 单次问答 | 持续学习 | 学习记录、进度文件、会话摘要，支持跨会话恢复 |
| 零散知识获取 | 结构化知识管理 | 章节 → 知识点 → 关系网络，索引与地图分离 |
| 主观判断掌握程度 | 基于证据的诊断 | 四层目标、评分量表、掌握状态迁移规则 |
| 单一课程工具 | 可扩展的通用框架 | 内核与课程模块分离，课程只提供结构与资料索引 |
| 个人工具 | 开放协作的社区项目 | Apache-2.0、模块规范、Issue/PR/Discussions |

### 2.3 三条底线

1. **不捏造**：没有资料支撑的内容标为推断或待验证，不编造教材原文、条文、案号。
2. **不越权**：不改原始资料，不静默覆盖用户文件，不擅自上传个人数据。
3. **不夸大**：没有测试证据就不改掌握状态，没有验证过的能力就不写进 README。

## 4. 工作原理与系统架构

### 4.1 三层分离

```text
┌─────────────────────────────────────────────────────────┐
│  Core（通用学习内核）                                     │
│  学习流程 · 知识管理 · 诊断量表 · 来源核验 · 复习策略       │
│  与具体课程无关，所有法学课程共用                            │
├─────────────────────────────────────────────────────────┤
│  Modules（课程模块）                                      │
│  民法学 / 刑法学 / 宪法学 / ……                            │
│  课程大纲、教材版本、章节结构、课程专属评估方式               │
├─────────────────────────────────────────────────────────┤
│  Workspace（用户工作区，本地）                             │
│  个人课程资料、知识条目、学习记录、薄弱点、复习队列            │
│  不进入公共仓库，不上传                                    │
└─────────────────────────────────────────────────────────┘
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Core | 怎么学、怎么诊断、怎么核验、怎么复习 | 某一门课的具体知识 |
| Modules | 教什么、按什么顺序教、用什么资料、怎么考 | 学习流程与诊断规则 |
| Workspace | 用户自己的资料与学习痕迹 | 公共内容、他人数据 |

这样设计的原因：课程会换、教材会换、学校口径不同，但“如何组织知识、如何验证理解、如何复习”是共通的。把共通部分做成内核，新增课程时只需要提供课程结构与资料来源，不必重写整套学习逻辑。

### 4.2 一次学习的完整链路

```text
1. 会话启动
   └─ 读 profile → course.md → progress.md → knowledge/index.md
      → review/queue.md → diagnostics/gaps.md
2. 确定本次目标（章节 / 概念 / 诊断 / 复习）
3. 按需读取资料与知识点条目（不整库加载）
4. 讲解或出题 → 用户作答 → 评分 → 归因
5. 写回证据：学习记录、知识点掌握状态、薄弱点、复习队列
6. 输出下一步
```

### 4.3 掌握状态的证据链

每个知识点按四个层次分别记录：`未测试 → 学习中 → 待复测 → 已掌握`。

- 只有留下**实际作答证据**（日期、题目、得分）才能升级。
- 一次答错只登记“观察中”，重复出错或基础性错误才进入薄弱点档案。
- 复测必须换题；连续通过才延长复习间隔。

这条规则是项目与“聊天式辅导”的主要区别：它不允诺“讲过了就等于会了”。

### 4.4 渐进式加载

`SKILL.md` 只保留流程与硬性规则，细节按需读取：

```text
SKILL.md（入口，流程与红线）
├── references/   # 需要细节时读：知识管理、诊断、来源、复习
├── templates/    # 需要落文件时读：课程、学习记录、薄弱点
└── examples/     # 想看完整走查时读
```

这样做的直接好处是：日常对话不会把全部规则塞进上下文，长文档也不会挤占讲解空间。

├── log/                      # 学习日志与会话摘要
└── .backup/                  # 覆盖前备份

## 6. 安装与使用

### 6.1 安装 Skill

Agent Skills 的通用形态是“一个目录 + 一个 `SKILL.md`”。安装就是把本项目放进宿主 Agent 的 skills 目录，并**保证目录名与 `name` 字段一致**：`law-study-agent`。

个人级安装（常见路径，具体以宿主文档为准）。以下命令使用仓库地址 `https://github.com/liguoguo172018/LawStudyAgent`；如果仓库迁移，请同步替换 owner：

```bash
# macOS / Linux
git clone https://github.com/liguoguo172018/LawStudyAgent.git ~/.claude/skills/law-study-agent

# Windows PowerShell
git clone https://github.com/liguoguo172018/LawStudyAgent.git "$env:USERPROFILE\.claude\skills\law-study-agent"
```

如果宿主使用项目级 skills 目录：

```bash
# 在项目根目录
git clone https://github.com/liguoguo172018/LawStudyAgent.git .claude/skills/law-study-agent
```

目录应呈现为：

```text
<skills-dir>/
└── law-study-agent/
    ├── SKILL.md
    ├── references/
    ├── templates/
    └── examples/
```

> 若仓库根目录名不是 `law-study-agent`，请在复制时重命名目录。`name` 与父目录名不一致会不符合 Agent Skills 规范，部分宿主会拒绝加载。
>
> 兼容性说明：本版本仅按通用规范编写，**未对任何具体宿主做系统兼容性测试**。Claude Code、其他支持 Agent Skills 的客户端是否可用、以何种路径加载，请以对应产品文档为准；未经测试的组合不应视为已支持。

### 6.2 SKILL.md 的作用

`SKILL.md` 是 Skill 的入口文件，包含：

- YAML frontmatter：`name`、`description`、`license`、`compatibility` 等元数据，宿主在启动时用它判断何时加载。
- 正文：适用场景、启动流程、从资料到复习的完整工作流程、来源与数据保护红线。
- 路由表：什么任务读哪个 `references/` 文件。

宿主只在需要时加载正文，再按需读取参考文件。因此修改内容时，优先把细节写进 `references/`，保持 `SKILL.md` 精简。

### 6.3 导入自己的课程资料

1. 建立工作区：在任意位置新建 `law-study-workspace/`。
2. 把资料放进 `materials/<course-slug>/`，例如 `materials/civil-law/`。
   - 支持文本、Markdown、PDF、PPT、图片等，能否读取取决于宿主能力。
   - 扫描件、加密文件、图片型 PPT 可能需要额外转换工具；Agent 应先说明方案再操作。
3. 告诉 Agent 资料位置与课程信息：课程名、教材版本、学校口径、考试形式、每周可用时间。
4. **不要**把资料放进本仓库的 `examples/` 或 `references/`；个人资料应留在工作区。

### 6.4 初始化一门新课程

对 Agent 说：

```text
用 LawStudyAgent 帮我建一门课：
- 课程：民法学（civil-law）
- 教材：《民法学》第 X 版，<作者>，<出版社> <年份>
- 资料在 law-study-workspace/materials/civil-law/
- 目标：期末闭卷考试，能完成案例题
- 每周 4 小时
```

Agent 应执行：清点资料 → 确认范围 → 生成 `courses/civil-law/course.md` → 搭章节骨架 → 建 3–5 个示例知识点 → 汇报缺口。若它直接开始讲整章内容，说明没有按流程走。

### 6.5 开始一次学习任务

可以直接描述需求，Skill 会路由到相应流程：

```text
“继续上次的民法学，先看有哪些到期复习。”
“解释一下‘意思表示’和‘法律行为’的区别，用表格。”
“给我 3 道案例题，只考要件涵摄，先别给答案。”
“把我这次的错题记到薄弱点里，并安排复测。”
```

一次典型会话：

```text
你：继续民法学，今天学合同的订立。
Agent：（读进度与队列）上次到 3.1，今天有 2 条到期复习。先花 5 分钟复测，
      再进入 3.2 要约与承诺，最后留 1 道案例题。可以吗？
你：可以。
...
Agent：（学习结束后）本次更新了 3 个文件，登记 1 个薄弱点，复测安排在 3 天后。
```

## 7. 课程模块扩展

### 7.1 为什么需要模块

不同学校、不同教材、不同教师的课程范围与术语口径并不相同。把某门课的章节写死进 Skill，会让项目退化成“某一本教材的笔记”。因此课程模块只描述**这门课教什么**，不重复学习流程：

| 模块应包含 | 模块不应包含 |
| --- | --- |
| 课程名称、教材与版次、适用对象 | 通用诊断规则、复习算法 |
| 课程大纲、章节结构、学时安排 | 其他课程的个人笔记 |
| 知识点清单与关系 | 未授权的教材原文、课件、题库 |
| 课程专属核验方式与评估方式 | 个人成绩、薄弱点、隐私信息 |
| 公开资料来源的索引 | 受版权保护的全文附件 |

### 7.2 希望支持的课程

- 民法学
- 刑法学
- 宪法学
- 行政法学
- 法理学
- 诉讼法学（民事、刑事、行政）
- 其他法律相关课程与法律硕士联考科目

当前仓库**只有 1 个虚构示例课程**（`examples/demo-course.md`），没有收录任何真实高校课程模块。上表是希望支持的方向，不是已有成果。

### 7.3 贡献课程模块

1. 以 `templates/course-template.md` 为骨架，填写课程信息。
2. 标注教材名称、作者、版次、出版社、出版年；不同版本请分别说明差异。
3. 只提交**结构、公开资料索引与原创说明**，不提交教材正文、教师课件、付费课程内容、题库。
4. 每个知识点注明来源类型与核验状态；无法核验的写“待验证”。
5. 在模块 README 中说明适用范围、已知缺口、维护者与更新日期。
6. 提交 PR 前自查：无个人数据、无版权风险文件、无虚构来源。

> 课程模块应遵循统一规范。未标注教材版本或来源的模块不会被合并；含有未授权资料的文件将被移除。

## 8. 使用示例

完整示例见 [`examples/demo-course.md`](examples/demo-course.md)。它以虚构课程《法理学导论》演示了从建课、知识点条目、学习记录、诊断、薄弱点到复习队列的完整链路，全程使用原创内容，不引用任何教材。

下面是两个最小片段。

### 8.1 概念辨析

```text
你：法律原则和法律规则到底怎么区分？

Agent：
一句话：规则是“要件—后果”相对明确的规范，原则是提供理由与方向的准则。
[推断]（未指定教材，以下为通行理解，正式作答请以课程教材为准）

| 对比项 | 法律规则 | 法律原则 |
| --- | --- | --- |
| 具体化程度 | 有行为模式与法律后果 | 多为价值指引，不预设具体后果 |
| 适用方式 | 要件满足即涵摄 | 衡量、权衡，通常在有规则时退居其次 |
| 冲突处理 | 规则冲突看效力与特别法 | 原则冲突看权重与个案情境 |

易错点：把“应当”当成规则标志。原则条文也常用“应当”。
检测题：给一段规范文本，请判断它更接近规则还是原则，并指出两个理由。
```

### 8.2 诊断与记录

```text
你：我答错了，我以为原则可以直接优先适用。

Agent：先别急，我需要确认是“不知道适用顺序”还是“知道但漏了论证”。
       追问：如果已有具体规则，当事人主张直接适用原则，你会怎么回应？
你：（作答）
Agent：你的问题属于“原理不清”：知道原则有指导作用，但没说明
       “穷尽规则”和“更强理由”的论证负担。已登记为中等薄弱点，
       复测安排在后天，题目会换成另一个情境。
```

## 9. 当前版本与已知限制

**当前为 v0.1.0 早期实验版本。** 项目仍在持续完善，以下是明确限制，避免误解：

| 限制 | 说明 |
| --- | --- |
| 兼容性未验证 | 未对任何具体 Agent 宿主做系统测试；不同客户端的 skills 目录、文件权限、工具能力差异可能影响使用 |
| 无自动化脚本 | 本版本是纯指令与模板，不含数据校验、导入、统计脚本；文件一致性靠 Agent 遵循规则 |
| 诊断依赖单次表现 | 评分量表是设计出来的，尚未经过信度、效度检验；不宜当作能力评估依据 |
| 复习机制较粗 | 间隔为参考值，未实现个体化遗忘模型，也没有后台提醒 |
| 课程模块缺失 | 只有虚构示例，没有真实课程模块可供直接使用 |
| 资料解析受限 | 扫描件、图表、公式、加密 PDF 的读取取决于宿主，可能需要用户手动补充 |
| 法条时效性 | 模型记忆可能过时；项目要求核验，但无法保证每次都能访问权威来源 |
| 无学习效果数据 | 未开展用户研究，不声称能提升成绩或通过率 |

### 验证情况（截至 2026-11-10）

- **已完成**：本地格式检查（YAML 字段与命名、Markdown 链接、代码围栏、空文件、敏感信息关键词）通过；在符合 Agent Skills 命名要求的 `law-study-agent` 目录副本上运行官方 `skills-ref 0.1.1 validate`，结果为 `Valid skill`；按本 Skill 流程实例化一套虚构课程工作区（课程、2 个知识点、学习记录、薄弱点、复习队列），跨文件一致性检查通过。
- **未完成**：未在真实 Agent 宿主（Claude Code 或其他客户端）中加载；未用任何真实课程资料试用；未验证不同宿主的目录、权限与工具差异。
- 因此，上面的“已提供”只代表指令、模板与格式校验自洽，不代表宿主运行结果。

尤其注意：

- **不应将 AI 输出直接视为权威法律意见或未经核验的法律知识。**
- 涉及现行法、司法解释、考试范围的内容，务必回到官方数据库、指定教材或教师口径核对。
- 本 Skill 的规则要求不上传、不外发用户资料，学习记录只写入你指定的本地工作区；实际是否联网、是否上传仍取决于宿主 Agent 的权限与配置。请自行备份工作区，并注意本地文件的隐私与访问权限。
