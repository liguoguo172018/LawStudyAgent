# 学习诊断：目标层次、证据与薄弱点

本文件展开 SKILL.md §8。核心原则只有一条：**掌握状态由证据决定，不由讲解次数、学习时长或“感觉懂了”决定。**

## 1. 四层学习目标

| 层次 | 能做什么 | 常用题型 | 通过标准 |
| --- | --- | --- | --- |
| 记忆 | 准确说出名称、定义、条号、分类 | 填空、名词解释、列举 | 表述准确，关键要素齐全，无实质性错误 |
| 理解 | 解释为什么，说明要素之间的关系 | 简答、解释、举例 | 能用自己的话说明原理，能给出正确例子 |
| 辨析 | 区分易混概念、判断边界情形 | 对比表、判断并说明理由、改错 | 能指出差异点与判断标准，不被近似表述误导 |
| 应用 | 把规范用于新事实，完成涵摄 | 案例题、要件分析、变式题 | 争点、规范、涵摄、结论齐全，能处理一个变化条件 |

一条知识点的四层分别记录，互不替代：

- 记忆通过，不等于理解通过。
- 理解通过，不等于能在案例中用出来。
- 应用失败时，回查是要素没记住（记忆）、原理不清（理解），还是没识别出适用场景（辨析）。

## 2. 诊断会话流程

### 诊断前

1. 明确范围：哪门课、哪一章、哪几个知识点。
2. 明确层次：本次要测四层中的哪几层；默认从记忆开始，最多跨两层。
3. 查阅已有证据：`diagnostics/gaps.md`、条目中的“证据记录”、`progress.md`，避免重复测同一题。
4. 说明规则：先作答后看答案；可以要求提示，但会记录“使用了提示”。

### 诊断中

1. 一次只出一个知识点，题目由浅入深。
2. 用户作答前不给答案、不给选项暗示、不替用户补全。
3. 用户答错时先追问“你是怎么判断的”，区分是猜对、背对还是理解对。
4. 用户要求提示时，给最小提示（指向某个要件），并记录提示级别：无 / 方向提示 / 要件提示 / 直接告知。
5. 遇到用户明显不会的题，不纠缠，标记“未通过”，换下一题。

### 诊断后

1. 逐题给出：结论、依据、扣分点、改进动作。
2. 汇总：本次覆盖了哪些知识点、各层通过情况、主要错误类型。
3. 决定是否登记薄弱点（见 §6）。
4. 更新条目 `mastery` 与证据表，写明日期、题目、作答摘要、评分。
5. 给出复测时间与复测题型。

## 3. 题目设计

### 基本要求

- **一个题目一个主考点**：可以顺带考前置知识，但评分只针对主考点。
- **不泄题**：题干不出现答案，不使用“下列哪项正确，因为……”这种提示结构。
- **可判定**：有明确的对错或评分点，不写“谈谈你的看法”作为唯一题目。
- **有区分度**：同一知识点的记忆题与应用题不能是同一句话换个问法。
- **换题复测**：复测不得复用原题，至少改变事实、问法或材料。

### 题型与目标层次对应

| 目标层次 | 可用题型 | 避免 |
| --- | --- | --- |
| 记忆 | 名词解释、要素列举、条文定位 | 开放式讨论 |
| 理解 | 为什么、请解释、举例说明、改错 | 只考背诵 |
| 辨析 | 对比表、判断正误并说明理由、边界例归类 | 两个概念各问一遍定义 |
| 应用 | 短案例、要件涵摄、变式条件、程序排序 | 只问“该案适用什么规则” |

### 案例题的最小结构

```text
事实：3–6 句，含一个关键争点和一个干扰事实
问题：请指出争点，说明适用的规范，并逐要件判断
要求：结论 + 依据 + 对干扰事实的处理
```

干扰事实必须有意义（例如影响某个要件的成立），不能只是废话。

### 变式设计

同一知识点准备三个变式，用于复测：

1. **换事实**：构成要件不变，事实情境改变。
2. **换边界**：加入一个使要件不成立或例外的条件。
3. **换问法**：从“是否成立”改为“由谁主张”“如何救济”“与另一制度如何竞合”。

## 4. 评分

用四项打分，每项 0–2 分，总分 8 分：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 结论 | 错误或缺失 | 方向正确但不完整 | 明确、准确 |
| 依据 | 无依据 | 提到规范/原理但未展开 | 准确引用并说明作用 |
| 要素完整性 | 漏关键要件 | 要件基本齐全，个别不准 | 要件齐全，边界清楚 |
| 表达 | 混乱 | 可读但结构松散 | 结构清晰，术语准确 |

判定：

- 6–8 分：该层次通过（记录分数与证据）。
- 4–5 分：部分通过，状态记“待复测”，指出缺口。
- 0–3 分：未通过，回到低一层次排查。

评分要落到具体句子：“你的结论正确，但漏了‘以缔约为目的’这一要件，因此第 3 点只给 1 分。”

## 5. 错误归因

| 错误类型 | 表现 | 追问 | 修复方向 |
| --- | --- | --- | --- |
| 概念缺失 | 完全不知道定义或要素 | “这个词你听过吗？它大概指什么？” | 补定义与要素，做记忆检测 |
| 概念混淆 | 两个概念的定义、要件或效果串了 | “A 和 B 的区别是什么？” | 做对照表，练边界例 |
| 原理不清 | 知道结论但说不出理由，换个问法就错 | “为什么是这个结论？” | 讲原理与推导，做解释题 |
| 规则记忆错误 | 条号、期限、比例、主体记错 | “这条规则的准确表述是什么？” | 回到原文核对，做精确复述 |
| 适用错误 | 规则本身会，但用错场景或漏要件 | “这个事实满足哪个要件？” | 练涵摄，做变式案例 |
| 表达不完整 | 意思对但缺步骤、缺结论 | “你的结论是什么？依据哪一条？” | 给答题结构，练限时输出 |

一次错误可能同时属于两类，按主因归类，并在记录中注明次因。

## 6. 薄弱点登记

### 登记门槛

| 情形 | 处理 |
| --- | --- |
| 首次答错，属偶发（看错题、笔误、明显紧张） | 记“观察中”，不进档案；下次顺带复测 |
| 同一知识点重复出错（同一次诊断中两道不同题目连续失败，或跨会话再次失败） | 登记为薄弱点 |
| 基础性错误（前置概念缺失导致整题崩） | 登记，并登记前置知识点 |
| 已掌握后又出错 | 状态改为“待复测”，登记复发原因 |
| 用户自述薄弱但无证据 | 只记“待验证”，不出诊断结论 |

**不得为了凑档案而登记。** 没有实际作答证据的条目，不写进 `gaps.md`。

### 严重度

- `低`：单点、可通过一次复习修复。
- `中`：影响本章后续学习，需要专项练习。
- `高`：前置知识缺失或跨章影响，需要回到更早章节。

### 生命周期

```text
观察中 → 已确认 → 修复中 → 已修复
              ↘ 复发 → 修复中（提高优先级）
```

- 观察中：有失误但未达登记门槛，保留在会话记录里。
- 已确认：达到门槛，进入 `gaps.md`，有复测计划。
- 修复中：已安排针对性练习，尚未通过复测。
- 已修复：连续两次在不同的新题目上通过，记录日期与证据；不删除历史。
- 复发：已修复条目再次失败，重新打开，注明“复发”，不新建重复条目。

登记与更新用 [../templates/knowledge-gap.md](../templates/knowledge-gap.md)。

## 7. 掌握状态迁移

状态集合：`未测试`、`学习中`、`待复测`、`已掌握`。

| 当前 | 事件 | 新状态 | 必须记录 |
| --- | --- | --- | --- |
| 未测试 | 讲解过但未测 | 学习中 | 学习日期、内容 |
| 学习中 | 该层次测评通过（≥6/8） | 已掌握 | 日期、题目、分数、作答摘要 |
| 学习中 | 测评未通过 | 待复测 | 日期、错误类型、缺口 |
| 待复测 | 换题复测通过 | 已掌握 | 日期、新题、分数 |
| 待复测 | 复测再次失败 | 待复测 | 日期、复发原因；连续两次失败升级为高严重度薄弱点 |
| 已掌握 | 间隔后复测通过 | 已掌握 | 更新最近复测日期 |
| 已掌握 | 复测失败 | 待复测 | 日期、失败点；不删除原通过记录 |
| 任意 | 用户要求重置 | 未测试 | 原因；保留历史证据 |

硬性约束：

1. 没有作答证据，不得写“已掌握”。
2. 低层次失败不自动否定高层次历史通过，但高层次失败必须回补低层次。
3. 一次答错不得直接标“长期薄弱”。
4. 状态更新时间必须一并记录证据，不能只改状态。
5. 批量改状态（如导入旧笔记）必须有来源说明，不得凭空升级。

## 8. 复测

- **时机**：至少间隔一次学习会话；高严重度薄弱点在 1–3 天内复测，中等在一周内，低在下次相关学习时顺带。
- **题目**：新题，改变事实或问法；优先用“换边界”变式。
- **范围**：先测原知识点，再测一个前置知识点，确认不是连带问题。
- **通过标准**：达到原目标层次；若原来只测了记忆，复测通过不代表理解通过。
- **记录**：写入 `gaps.md` 的“后续复测结果”和条目的证据表。
- **未复测**：状态保持“待复测”，不因时间流逝自动变“已掌握”。

## 10. 常见误用

- 把“讲得很清楚”当作“学得很好”——讲解质量不等于学习结果。
- 用一道综合题判断多个层次——无法定位问题。
- 复测直接问“上次那道题还会吗”——测的是记忆痕迹，不是迁移。
- 用户答对就跳过依据追问——可能只是猜对。
- 把用户的自我评价写进诊断结论——自述只能作为线索，需证据支持。
- 诊断后不更新文件——下次会话无法恢复，等于没诊断。
