# 复习系统：从证据到排期

本文件展开 SKILL.md §9。核心想法：复习不是把所有知识点按固定间隔轮一遍，而是**由学习与复测的实际表现触发**，并按错误类型选择复习方式。

## 1. 原则

1. **检索优先**：先让学习者回忆、作答，再看资料；重读只用于补缺。
2. **间隔**：同一知识点分散到多次会话，优于一次集中重复。
3. **交错**：一次复习混合 2–3 个相关知识点，练习辨别，而不是单章刷题。
4. **针对性**：按错误类型出题——概念混淆练对比，原理不清练解释，适用错误练变式。
5. **可记录**：每次复习留下题目、作答、结果；没有记录的复习视为未发生。
6. **无后台推送**：本 Skill 不运行定时器、不主动提醒；复习只在会话读取队列时触发。

## 2. 触发规则

| 上次表现 | 复习优先级 | 建议间隔（参考） | 题型 |
| --- | --- | --- | --- |
| 答错或完全无法回忆 | 高 | 1–2 天 | 同层新题 + 前置检查 |
| 概念混淆 | 高 | 2–3 天 | 对比表、边界例归类 |
| 原理不清 | 中高 | 3–5 天 | 解释题、追问为什么 |
| 规则记忆错误 | 中 | 2–4 天 | 精确复述、条文定位 |
| 适用错误 | 中高 | 3–7 天 | 变式案例、要件涵摄 |
| 表达不完整 | 中 | 3–5 天 | 限时结构化输出 |
| 首次通过 | 低 | 7 天 | 同层新题 |
| 连续两次通过 | 低 | 14–30 天 | 跨层综合题 |
| 已修复薄弱点 | 低 | 30 天 | 迁移题、混合题 |

间隔是**参考值**，不是规则。调整依据：

- 连续通过 → 延长；
- 再次失败 → 缩短，并重开薄弱点；
- 临近考试 → 压缩间隔，增加整卷式练习；
- 长时间中断（>30 天）→ 先做诊断性抽测，再决定排期，不直接按旧状态继续。

## 3. 复习队列

文件：`review/queue.md`。

```markdown
# 复习队列

> 只登记需要复习的条目；到期日按证据推算，不是固定日历。

| 到期日 | 课程 | 知识点 id | 知识点 | 上次结果 | 错误类型 | 目标层次 | 复习原因 | 建议题型 | 最近复测 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-11-12 | civil-law | civil-03-02 | 要约的构成 | 部分 | 适用错误 | 应用 | 漏“受约束意旨”要件 | 变式短案例 | 2026-11-10 |
| 2026-11-17 | civil-law | civil-01-05 | 诚信原则 | 通过 | - | 理解 | 首次通过 | 举例说明 | 2026-11-10 |
```

字段规则：

- `到期日`：按上次表现与参考间隔推算；改期要写原因。
- `上次结果`：通过 / 部分 / 未通过 / 未测。
- `目标层次`：本次要测的层次，不写“全部”。
- `复习原因`：必须具体（“漏某要件”），不写“巩固一下”。
- `建议题型`：与错误类型对应，见 §2。
- `最近复测`：留空表示尚未复测。

排序：逾期 → 今日到期 → 本周到期 → 无到期日的新条目。一次会话最多处理 5–8 条，避免疲劳。

## 4. 复习会话流程

### 开始

1. 读 `review/queue.md` 与 `diagnostics/gaps.md`。
2. 取出逾期与今日到期条目；若用户时间有限，优先高严重度薄弱点。
3. 向用户报告：今天有几条到期、预计用时、覆盖哪些知识点。
4. 选 2–3 个相关知识点交错排列，不按章节顺序。

### 进行

1. 先测后讲：每题先让用户作答。
2. 答错时给最小提示，记录提示级别。
3. 讲评只讲缺口，不重讲整章。
4. 同一知识点连续两次失败，停止刷题，回到概念或前置知识。
5. 时间到就停，未完成条目顺延并改到期日。

### 结束

1. 逐条更新队列：结果、最近复测、下次到期日、原因。
2. 更新知识点 `mastery` 与证据表。
3. 更新或新开 `gaps.md` 条目。
4. 追加学习日志与会话摘要。
5. 报告：通过 / 部分 / 未通过各几条，下一步安排。

## 5. 按错误类型出题

| 错误类型 | 出题方式 | 通过标准 |
| --- | --- | --- |
| 概念缺失 | 名词解释 + 要素列举 | 要素齐全、无实质错误 |
| 概念混淆 | 给一个边界例，问属于 A 还是 B，并说明判断标准 | 分类正确且理由指向关键差异 |
| 原理不清 | 问“为什么”，要求给出推导链 | 能说出理由与反例 |
| 规则记忆错误 | 精确复述条文/期限/主体，或给错句改错 | 关键数字与主体准确 |
| 适用错误 | 变式案例，改变一个事实条件 | 重新完成涵摄，结论随事实变化 |
| 表达不完整 | 限时 5 分钟写答题结构 | 争点、规范、涵摄、结论齐全 |

题目要**新**：不改数字、只改主语不算新题；至少改变一个影响判断的事实或问法。

## 6. 薄弱点与复习的联动

- 高严重度薄弱点：进入队列顶部，每 1–3 天复测，直到连续两次在不同的新题目上通过。
- 中严重度：每周至少一次，穿插在正常复习中。
- 低严重度：随相关章节复习顺带处理。
- 已修复：保留记录，30 天后做一次迁移题；再次失败则重开并提高严重度。
- 不在队列中的知识点也可以抽测，但抽测结果要回写，不能测完就丢。

## 7. 长期未复习的处理

中断超过 30 天：

1. 不假设旧状态仍有效。
2. 每门课抽 3–5 个知识点做诊断性抽测，覆盖不同章节与层次。
3. 按结果重排优先级：失败的优先，通过的延长间隔。
4. 在 `progress.md` 记“中断后复测”，说明抽测范围与结论。

中断期间不产生“逾期堆积”焦虑式提示；只报告实际到期数量。

## 8. 复习计划（plan.md）

`review/plan.md` 记录策略而非具体任务：

```markdown
# 复习策略

- 目标：<考试/理解/应用>
- 可用时间：每周 <n> 次，每次 <n> 分钟
- 优先级：高严重度薄弱点 > 逾期条目 > 新学内容
- 交错规则：每次混合 2–3 个相关知识点
- 考试前两周：整卷练习 + 错题回炉
- 不承诺后台提醒；以会话读取为准
```

策略变化时更新并写原因。

## 9. 周复盘

每周（或每 5 次学习会话）做一次：

- [ ] 统计：本周新增知识点、通过/未通过数、薄弱点新增与修复数。
- [ ] 检查逾期条目，判断是时间不足还是题目过难。
- [ ] 检查“已掌握”条目是否长期未复测（>30 天），安排抽测。
- [ ] 检查是否有反复失败的知识点（连续 3 次），考虑回补前置或换讲法。
- [ ] 更新 `progress.md` 与 `plan.md`。
- [ ] 向用户报告趋势，不只报数字；不夸大进步。

## 10. 记录格式

每次复习在学习日志中追加一行：

```markdown
| 2026-11-12 | civil-law | 复习：要约的构成、承诺生效 | 3 题，2 通过 1 部分；补“受约束意旨”要件 | 队列已更新 |
```

会话摘要中记录：

```markdown
## 复习结果
- 覆盖：civil-03-02、civil-03-04
- 通过：1；部分：1
- 新增薄弱点：无
- 下次到期：2026-11-15（civil-03-02）
```

## 11. 边界

- 不声称能“科学预测遗忘曲线”——参考间隔来自一般学习原则，不是针对个人的精确模型。
- 不用复习次数代替掌握证据。
- 不因为“今天没复习”而虚构已完成记录。
- 不在用户未确认时批量改到期日或清空队列。
